# ASEMA v0.1 — Implementation Plan

## 1. Current State & Missing Components

Prior to this implementation, no ASEMA codebase existed. All 20 phases specified in the master specification must be systematically engineered from ground truth:

1. **Storage Subsystem (`ASEMA-SSF`)**: Missing. Needs 64-byte aligned binary format + `manifest.json`.
2. **Synchronous & Asynchronous Expert Loader**: Missing. Needs non-blocking background loading, I/O latency accounting, CRC32/SHA256 integrity validation.
3. **RAM Cache (`ExpertRAMCache`)**: Missing. Needs thread-safe LRU eviction, hard/soft memory reservations, per-layer hit/miss tracking.
4. **Request Priority Queue (`ExpertRequestQueue`)**: Missing. Needs priority tiers (`REQUIRED_NOW`, `PREFETCH`, `BACKGROUND`).
5. **Prefetch Engine**: Missing. Needs deterministic next-layer and locality lookahead, cancellation, wasted vs useful metrics.
6. **Telemetry Engine**: Missing. Needs per-token micro-metrics, JSONL telemetry export, and human-readable reporting.
7. **Synthetic MoE Generator**: Missing. Needs parametric $N$-layer, $M$-expert, top-$k$ routing model for verifiable benchmark runs.
8. **Inference Runtime (`ASEMARuntime`)**: Missing. Orchestrates routing, cache check, async wait, execution, prefetching.
9. **Benchmark CLI (`asema-bench`) & Tools (`asema-pack`, `asema-inspect`)**: Missing.
10. **Validation & Verification**: Unit tests, stress tests (1,000 to 10,000 requests), memory thrashing tests, and real MoE validation.

---

## 2. Dependencies & Build Strategy

- **Language Standard**: Modern C++20 (`std::jthread`, `std::latch`, `std::atomic`, concepts, filesystem).
- **Core Dependencies**:
  - `nlohmann/json` (single-header) for manifest parsing/serialization.
  - Windows Native Asynchronous I/O (`OVERLAPPED` / IOCP thread pool) wrapped in an abstract `StorageBackend`.
  - Python 3.11 with PyTorch/Transformers for reference baseline and model pack converter.
- **Build System**: CMake + Ninja / LLVM-MinGW (Clang++ with UCRT).

## 4. Risks & Mitigations

| Risk | Mitigation |
| :--- | :--- |
| Asynchronous I/O thrashing under heavy lookahead | Memory reservation counter + bounded request queue before issuing I/O. |
| Inaccurate latency measurements | High-resolution monotonic timers (`std::chrono::steady_clock`) capturing timestamps at queue entry, disk read start, completion, and cache insert. |
| Memory budget overrun during concurrent loads | Pre-allocation reservation system: space is reserved in RAM cache before issuing disk read. If insufficient, eviction triggers synchronously before read. |
